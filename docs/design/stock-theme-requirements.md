# 股票主题篮子分类 — 需求文档

> **日期**: 2026-11-27
> **状态**: 已确认（2026-11-27 Boss 确认，并经 Phase 3 异构架构审核同步对齐口径）
> **Linear 项目**: `P-OWE-10`（股票主题分类）
> **北极星定位**: 主北极星第一层「数据层（Data Desk）」的基础分类字段与篮子归属底座；上层篮子涨跌、资金流向、拥挤度计算与看板展示归属更上层模块，不在本期范围。

---

## 1. 动机

- **服务上层「主题篮子」量化监控**：重构目的不是给单只股票贴静态展示名片，而是构建边界清晰、人数达标的**主题篮子**，供上层模块统计篮子整体表现、判断市场资金流向与交易拥挤度。
- **解决颗粒度失衡问题（以 `MU` 为锚点确立三层分工）**：
  1. **L1 大板块（如 `半导体`）**：池内股票过多、内部涨跌互相抵消，只做一级目录与大盘资金水位分母，不与主战篮子混排。
  2. **L2 互斥赛道篮子（如 `存储`、`光与高速互连`、`半导体设备`）**：核心计算单元。按“市场资金一起买卖的投资逻辑”切分而非传统会计行业切分；每只符合入篮条件的美股**有且仅有 1 个 L2 赛道**，保证全池资金流加总严格等于 100%，零重复刷屏；新建篮子设人数门槛（主池内原则上 ≥ 4~5 只）。
  3. **精选纯产业跨界大主题篮子（如 `AI 算力基建`、`AI 电力缺口`、`加密生态`）**：独立于 L2 的横向产业叙事大篮子（彻底剔除宏观风格与政策风险标签），允许一只美股挂 `0..N` 个跨界大主题，单独成榜观察跨赛道大叙事抱团，不污染 L2 互斥资金加总。
  4. **砍掉原 L3 细碎概念篮子**：人数不足以成篮的细分词条（如美股主池内仅 `MU` 1 只的 `HBM`）一律不建篮子，杜绝个股披多个马甲霸榜。
- **彻底清偿三代历史技术债**：清理仓库内叠床架屋的三代旧分类栈（第一代 14 粗桶 JSON 与独立 `themes.py`、第二代废弃的 10-K 图谱残留表、第三代 2,087 行 `CSV ⇔ DB` 双写脚本与 61.4% 漏标跨界主题的死规则体系）。

## 2. 用户

- **上层业务模块（核心调用方）**：后续建设的主题篮子表现/资金流/拥挤度模块、美股晨报、景气与动量模块、Portfolio Intelligence 及 CIO 组合敞口诊断（单一主题 35% 仓位上限校验）。
- **研究与工程 Agent**：通过统一短连接 Python 只读接口按股票查所属篮子，或按篮子拉取成分股集合。
- **Boss 本人**：低频把关者——仅在审定初始「篮子目录与首轮全池打标结果」、维护核心票锁定及新增跨界大主题时拍板，日常零 CSV 审表负担。

## 3. 场景

1. **篮子目录审定与首轮全池异构双盲精标**：先设计 L1、L2 互斥赛道与纯产业跨界大篮子完整清单，经 Boss 审定后，对目标池（约 950~1,050 只）完成主控 + 异构盲审双通精标并写入云端权威 `market.db`。
2. **上层模块只读读取**：上层模块直接从 `market.db` 短连接读取股票的 `(L1, L2, 跨界大篮子列表)`，或按篮子 ID 获取活跃/历史时点成分股列表。
3. **周日本机 AGY 订阅自动增量分类**：每周日（云端周六池刷新与本地周日拉取完成后），由本机三明治隔离流水线唤醒受限 AGY Sidecar，使用订阅配额对当周新进池股票完成分类并经受限 SSH 幂等写入云端权威 `market.db`；单只异常坏票隔离进周摘要告警（下周自动重扫补标），合格新票正常入库；跌破市值门槛出池的老票保留分类不删除；在池老票若发生更名或 FMP 行业变更，仅自动复核并在摘要提示（只报不改）。
4. **双级手工锁定纠偏**：公开大盘跨界巨头（如 `AMZN`、`TSLA`、`MU`、`VRT`）写入 Git `overrides.json`；个人私密中小盘持仓/观察票通过受控命令以 `source='db_locked'` 锁在云端私有 `market.db` 内（不进公开 Git）；两类锁定均拥有最高优先级，重跑永不覆盖。
5. **跨界大篮子低频演进**：当市场涌现新的持续性大主线且池内纯正标的达到成篮门槛时，在 Git 篮子字典新增定义并跑增量补标（旧篮子只停用不物理删除）。
6. **平滑切换与旧栈清零**：周日自动化跑通验证后，通过薄兼容接口无缝接管线上 `morning_report.py` 与 `portfolio_intelligence.py`（存量票逐票冻结 `pi_bucket` 保持 `40% NAV` 告警语义不变），验证稳定后一次性删净全部三代旧代码、旧 CSV/JSON 与幽灵表。

## 4. 产品形式

- **严守 Data Desk 数据层边界**：
  - 云端权威 `market.db` 内的篮子定义、股票归属、跨界关联、变更历史与同步心跳 5 张表（本地仅通过 `--pull` 持有只读副本）；
  - Git 跟踪的轻量配置文件：篮子字典定义（`baskets.json`）+ 公开大盘龙头锁定表（`overrides.json`）；
  - 本机 `launchd` 前后置确定性脚本 + 零命令权限 AGY 定时自动化任务（`sidecar.json`）；
  - 短连接即用即关的 Python 只读查询接口（含对现有晨报/PI 的过渡兼容层与 `data_health.py` 监控项）。
- **明确不做（Non-Goals）**：
  - 本期不计算篮子涨跌幅、资金净流入、内部齐涨率或拥挤度指标；
  - 本期不开发 HTML 看板或新增日常行情推送；
  - 本期不重构美股晨报或 PI 版式（仅替换其底层概念标签读取源）。

## 5. 输入 / 输出

**覆盖范围**
- **`Extended 主池`（市值 ≥ 100 亿美元非 ETF 美股，含当前活跃与历史入池约 900~1,011 只）∪ 显式 `Overlay`（线上 PI 只读主账 `Google Sheet` 实时持仓 ∪ `company.db:watchlist`）**（注：`company.db:holdings` 已于 `7b9ad9d5` 退役，不再读取）。
- **异构标的隔离**：`Overlay` 中的 ETF（如 `QQQ`、`SOXX`）、自定义篮子（如 `DRAM`）、封闭式基金（`DXYZ`）、加密资产及非美股持仓，由确定性前置逻辑标记 `in_us_basket_calc=0`（跨市场代码带 `HK:/KR:/CRYPTO:` 前缀），**严禁混入美股个股 L2 赛道或跨界主题篮子统计**。

**输入**
- `market.db`：`extended_membership`、`security_master`、`company_profile`。
- 只读主账 `Google Sheet`（宽松扫描代码与市场列，不可达时显式标 `UNKNOWN`）与 `company.db:watchlist`。
- Git 配置文件：`baskets.json` + `overrides.json`。
- 本机 Antigravity 订阅模型能力（第一版异构双盲批处理 + 后续周日 AGY 定时任务）。

**输出**
- `market.db` 分类与历史记录：每只美股主代表股具备非空 `l1_id`、唯一非空 `l2_id`、`0..N` 个合法跨界主题（区分 `core` / `platform_giant`）、逐票 `pi_bucket`、简短业务备注、分类来源（`override / db_locked / agy_llm`）、一致性状态（`locked / dual_agreed / single_pass_weekly / needs_spot_check / disagreed`）、时间戳及只追加变更历史 `stock_theme_history`。
- Python 短连接只读查询 API：支持单票/批量查分类（保留 `LEAPS/PUT` 衍生品方向，支持双股类与改名透明归一化）、按 L1 / L2 / 跨界篮子反查活跃或 `as_of` 成分股，以及晨报/PI 兼容读取。
- 周日同步日志、`theme_sync_commits` 幂等心跳记录与 Telegram 简短运维摘要。

## 6. 约束

- **P3 所有权与本地零写库铁律**：`market.db` 云端权威独占写入，**本地严禁写入 `market.db` 且读连接必须即用即关**，仅通过 `sync_to_cloud.sh --pull` 获取快照；彻底废除 `CSV ⇔ SQLite` 双状态同步。
- **严禁触碰景气引擎 `CODE_VERSION_SOURCES`（关键工程红线）**：新模块严禁修改 `terminal/prosperity/version.py:CODE_VERSION_SOURCES` 所列全部 11 项文件/目录中的任一字节（含 `market_store.py`、`settings.py`、`symbol_aliases.py`、`symbol_aliases.json` 等），也严禁被其 `import`；实施前后 `main` 的 `code_version()` 必须完全恒等。
- **三明治安全隔离与幂等自愈**：AGY Sidecar 不挂工作区、零命令执行权限，仅读写仓库外交换目录；Step C 校验 `delta_sha256` 与待标子集，经 `restrict,command` 受限 SSH 提交云端，按 `payload_id` 幂等去重；差集按状态求差完全幂等。
- **校验门控与逐票隔离**：每个连接开启 `PRAGMA foreign_keys = ON` 并配合触发器锁死层级与异构隔离；字典/结构级违例整批 fail-closed 拦截，周频单只异常票逐行隔离告警（不连坐阻断同批合格票）。
- **开发与部署纪律**：所有代码在独立 git worktree 内按 TDD 开发；合并、push、云端部署与清理旧栈每步独立确认。

## 7. 成功标准

- **S1 篮子字典定稿**：产出一套贴合资金交易逻辑的「L1 大板块 + L2 互斥赛道篮子 + 纯产业跨界大主题篮子」定义表（满足新建成篮人数门槛，剔除宏观风险标签），经 Boss 审阅签字。
- **S2 首轮全量异构双盲精标覆盖**：完成 `Extended ∪ Sheet ∪ watchlist` 异构双盲精标落库，存量票逐票冻结现有 PI 分桶，消灭无标签缺口、双股类双算与死规则空壳，Boss 抽检核心篮子与分歧票通过。
- **S3 本机周日三明治自动化闭环**：部署周日 10:00 `launchd` + 受限 AGY Sidecar 流水线并通过端到端试跑与越权拦截反向测试。
- **S4 无缝接管与旧三代清零**：`morning_report.py` 与 `portfolio_intelligence.py` 切至新表（真实持仓逐票对拍 `pi_bucket`，差异清单经 Boss 签字，图片报告零丢行）；随后一次性删净 ~3,500 行旧分类业务代码、37 份旧 CSV/manifest、旧 JSON、`sync_to_cloud.sh` 残留 CSV 段及 3 张幽灵表（保留无关视图 `v_top_adv_trailing30bars`；`market_store.py` 内 4 张旧表清空留 0 行空壳，其空表 DDL 与 `config/settings.py:156,423-424` 的 3 个旧常量一并挂单搭下次景气主动升版顺手删除，确保本期实施前后 `code_version()` 恒等）。
- **MVP 定义**：`S1 + S2` 为核心数据交付里程碑；`S3 + S4` 为同项目收官交付。

## 8. 风险

| 风险 | 后果 | 架构应对措施 |
|---|---|---|
| L2 赛道或跨界篮子切分不符合真实资金交易逻辑 | 上层算出的资金流与拥挤度失真 | 对照本库 856 只主池实盘分布试切；S1 由 Boss 先审篮子与代表股再全量铺开 |
| 多元化公司主赛道归属摇摆或私密小票纠偏无处存 | 重跑时核心股跳篮子或泄漏隐私 | 公开巨头用 Git `overrides.json` 锁死，私密票用云端库内 `db_locked` 锁死，存量行默认拒绝自动覆盖 |
| 第三方公司简介夹带恶意提示词尝试越权读密钥或连云端 | 私钥或账本凭证泄露 | Sidecar 不挂工作区、零命令权限，仅读写仓外交换目录；Step C 验 `delta_sha256` 并走 `restrict,command` 受限 SSH |
| 本机合盖错过周日窗口，或 Google Sheet 临时不可达 | 当周几只新票延后打标或漏扫持仓 | 状态求差下次唤醒自动追平；Sheet 不可达显式标 `UNKNOWN` 标红告警；`data_health.py` 监控同步心跳与未标计数 |
| 触碰 `CODE_VERSION_SOURCES` 11 项文件改变景气 `code_version` | 云端景气冻结链版本失效 | 新模块物理独立，4 张旧表先留空壳搭车删 DDL，测试断言实施前后 `code_version()` 恒等 |
| 切换底层表导致 PI `40% NAV` 口径漂移或图片丢行 | 影响日常生产报告 | M4 逐票冻结存量 `pi_bucket`，固化原 15 桶清单，M6 真实持仓逐票对拍签字后再切 |

## 需求清单

- **R1（定位与边界）**：系统限定为 `market.db` 数据层分类底座，只负责维护篮子字典、股票归属与变更历史并提供短连接只读接口，不计算篮子表现、资金流或拥挤度。
- **R2（三层分类模型）**：采用「L1 大板块（目录/分母）+ L2 互斥主战赛道篮子（1 股必属且仅属 1 篮）+ 精选纯产业跨界大主题篮子（1 股可属 `0..N` 篮，区分 `core/platform_giant`）」结构，取消原 L3 细碎概念篮子与宏观风险标签。
- **R3（成篮规模与交易逻辑切分）**：L2 赛道与跨界大篮子按真实市场资金共振逻辑划分，新建篮子须满足最小活跃人数门槛（原则上 ≥ 4~5 只；新兴纯正高弹性或极端寡头赛道经 Boss 特批可设 2~3 只，如 `Neocloud` 与 `AI加速芯片`），已启用篮子只停用不物理删除。
- **R4（股票池与异构资产隔离）**：覆盖 `Extended 主池（$10B+）∪ Google Sheet 当前持仓 ∪ company.db:watchlist`；通过确定性 `asset_kind` 与 `in_us_basket_calc=1/0`（跨市场代码强制带 `HK:/KR:/CN:/CRYPTO:` 前缀）隔离，仅美股单公司主代表股 `=1` 参与篮子统计；跌出主池的老票保留分类，且对 `security_master.eligible=1` 且近 10 日内 `historical_market_cap ≥ 100 亿美元` 的主代表股做活跃防蒸发兜底。
- **R5（云端唯一写点与本地禁写）**：废除 `CSV ⇔ SQLite` 双状态同步，云端权威 `market.db` 为唯一写点，本地严禁写 `market.db`，仅通过 `--pull` 同步快照。
- **R6（第一版全池异构双盲精标）**：在第一版开发阶段通过主控 + 异构盲审完成覆盖池全部标的精细打标，消灭无标签缺口、双股类双算与死规则空壳。
- **R7（双级手工锁定最高优先级）**：支持 Git `overrides.json`（公开龙头）与云端库内 `db_locked`（私密标的）双级锁定，优先级高于一切自动分类，存量行拒绝自动覆盖，队列发送时实时嵌入最新配置。
- **R8（周日本机仓外三明治自动化）**：每周日 10:00 通过本机 `launchd` + 零命令权限 AGY Sidecar 幂等检测新进池股票与老票异动（老票只报不改），经受限 SSH 按 `payload_id` 幂等提交云端并发送 Telegram 摘要。
- **R9（数据库触发器与逐票隔离校验）**：开启外键并由触发器强制校验层级归属与跨界表纯度；结构错误整批拦截，周频单票异常隔离告警不连坐合格新票。
- **R10（短连接只读查询与精确兼容接口）**：提供即查即关只读 API（支持动态建库日 `as_of` 历史还原与保留 `LEAPS/PUT` 方向），逐票冻结存量 `pi_bucket` 兼容晨报与 PI（零丢行、保 `40% NAV` 口径）。
- **R11（景气 `code_version` 相对恒等）**：新模块零触碰 `CODE_VERSION_SOURCES` 全部 11 项文件/目录，确保实施前后 `main` 的 `code_version()` 完全相等。
- **R12（三代遗留栈彻底清理）**：在新表与周日自动化验证稳定后，同一项目内删净三代旧分类代码、37 份旧 CSV/JSON、`sync_to_cloud.sh` 残留 CSV 段与 3 张幽灵表，清空 `market_store.py` 4 张旧表数据并将死 DDL 挂单搭车删除。
