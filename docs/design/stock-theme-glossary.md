# 股票主题篮子分类 — 术语表

> **日期**: 2026-11-27 ｜ 配套 `stock-theme-requirements.md`、`stock-theme-research.md`

---

## 一、分类层级与篮子结构

| 术语 | 大白话含义与本项目口径 |
|---|---|
| **L1 大板块** | 一级行业目录（约 10~12 个，如 `半导体`、`金融`）。股票太多、内部涨跌互抵，只做大盘资金占比的分母和折叠目录，不和细分篮子混排。 |
| **L2 互斥赛道篮子** | 主战分类单元（约 40~55 个，如 `存储`、`光与高速互连`、`北美区域银行`）。每只符合资格的美股**有且仅有 1 个 L2 赛道**，全市场资金流加起来正好 100%，不重不漏。 |
| **跨界大主题篮子** | 横跨多个行业的纯产业投资大主线（精选约 10~15 个，硬上限 ≤ 18 个，如 `AI 算力基建`、`AI 电力缺口`）。一只美股可挂 `0..N` 个跨界大主题，单独一张榜观察大叙事抱团，不污染 L2 互斥资金加总。 |
| **成篮人数门槛** | 一个篮子要能算出靠谱的涨跌均值、内部齐涨率和相关性拥挤度，主池内至少要有 **4~5 只**（理想 **8~25 只**）同逻辑美股；凑不够人数的细碎概念（如美股仅 `MU` 1 只的 `HBM`）一律不建篮子。 |
| **会计营收锚 vs 市场定价锚** | 传统行业分类（如 GICS、RBICS Focus）按“过去一年哪块收入超过 50%~60%”分桶（会计锚，把 `AMZN` 分进零售）；本项目按“二级市场资金当前围绕哪块核心利润和逻辑给它定价”分桶（定价锚，`AMZN` 归云计算）。 |
| **`Enabler`（卖铲人）vs `Adopter`（用铲人）** | 摩根士丹利主题分类核心概念：`Enabler` 是直接卖芯片、光模块、变压器、电力的供给侧瓶颈公司；`Adopter` 是买软件或用 AI 降本增效的普通银行、零售商。跨界主题篮子**只收卖铲人，硬性排除用铲人**，防止全市场大公司混入。 |
| **`Pure-Play`（纯正股）vs `Quasi-Play`（半路/局部股）** | 指数机构纯度术语：`Pure-Play` 主营业务大半直接来自该主题；`Quasi-Play` 只有一部分业务受益（如大型综合集团）。公募 ETF 为凑够税法要求常塞入边缘股，本项目不为凑人数放宽纯度。 |
| **`Overrides`（手工锁定表）** | Git 里维护的一份轻量钦定清单。Boss 拍板锁死的巨头或边界股（如 `AMZN`、`TSLA`、`MU`、`VRT`）写在这里，拥有最高优先级，任何自动重跑都绝不覆盖。 |

## 二、股票池、证券身份与覆盖边界

| 术语 | 大白话含义与本项目口径 |
|---|---|
| **`Extended` 主池** | FMP 筛选出的纽约/纳斯达克上市、市值 ≥ 100 亿美元的非 ETF/非基金普通股（及合规 ADR），是系统默认的机构主战场股票池（当前活跃 856 只，含历史进出共 1,011 只）。 |
| **显式 `Overlay`（叠加关注池）** | 线上 PI 只读主账 `Google Sheet` 实时持仓（市场含 `US/HK/KR/CRYPTO`）∪ `company.db:watchlist`（含港/A 股观察标的；原 `company.db:holdings` 已退役）。用来把不满 100 亿美元但正在跟踪的美股纳入分类，同时登记跨市场持仓、ETF、自定义篮子与加密资产（私密标的只存云端 `market.db`，不进公开 Git）。 |
| **双股类（Dual Share Class）与主代表代码（`canonical_symbol`）** | 同一家公司发行的多类或跨所股票（如 Alphabet 的 `GOOG` 与 `GOOGL`、嘉年华的 `CCL` 与 `CUK`）。篮子成分统计时一家公司只准进 1 个主代表代码（防成交额与等权涨跌翻倍）；查询任意代码自动映射到同一套篮子标签。 |
| **代码变更别名（`symbol_aliases`）** | 同一家公司改名换代码（如 Pure Storage 从 `PSTG` 改为 `P`、Square 从 `SQ` 改为 `XYZ`）。分类跟新代码走，旧代码标 `is_superseded=1` 保留历史可查。 |
| **`asset_kind` 与异构非入篮标的** | Step A 确定性判定的 7 类资产身份（`us_equity / etf / fund_cef / non_us_equity / crypto / custom_basket / other`）。除美股普通股外一律强制 `in_us_basket_calc=0`，且跨市场代码强制带 `HK:/KR:/CN:/CRYPTO:` 前缀防撞键。 |
| **双级锁定（`override` 与 `db_locked`）** | 公开大盘龙头锁在 Git `overrides.json`（最高优先级）；个人私密持仓/观察小票的手工纠偏通过受控命令以 `source='db_locked'` 锁在云端私有 `market.db` 并备份至仓外本地目录，均拒绝自动覆盖。 |
| **`pi_bucket`（PI 15 粗桶冻结列）** | 专供 `portfolio_intelligence.py` 使用的粗粒度分桶字段（15 个桶统一存入 `theme_baskets` 表同源管理）。首轮落库时逐票冻结存量票旧分桶，保证线上 `≥40% NAV` 集中度告警语义不变且图片零丢行。 |
| **次优竞争赛道（`runner_up_l2_id`）** | 仅在校验期 JSON 中使用的辅助字段（不落数据库）：让模型填出最纠结的第 2 候选赛道（无疑问填 `null`），用来抓出跨界模糊票。 |
| **`payload_id`（分类行内容哈希）** | 待提交新票分类行集合的 SHA256 指纹，记录在云端 `theme_sync_commits` 表中，确保网络断线重放同一批次时幂等去重。 |
| **RIC `25/5/50` 分散化规则** | 美国税法对公募 ETF 的硬规定（单股不超 25%，权重 ≥5% 的股票合计不超 50%），迫使公募主题 ETF 至少硬凑 20~25 只股票。本项目是内部交易台底座，不受此税法限制，不必拿边缘股凑数。 |

## 三、打标机制、防前视与工程红线

| 术语 | 大白话含义与本项目口径 |
|---|---|
| **封闭集分类（Closed-World Taxonomy）** | 模型只能从 Git 篮子字典里已定义好的合法篮子 ID 中选择，严禁临时自造新词，落库前做确定性枚举与外键校验。 |
| **推理前置 Schema** | 大模型结构化输出按字段定义顺序逐字生成。把“一句话提炼主业”和“排除条件核对”排在“篮子 ID”字段前面，逼模型先核实业务再选标签，避免先盲猜后编理由。 |
| **次优竞争赛道（`runner_up_l2_id`）** | 让模型在选出唯一主赛道 `l2_id` 的同时，填出最纠结的第 2 候选赛道（无疑问则填 `null`）。比模型自报虚高的 `0.95` 置信度更能抓出真正的跨界模糊票。 |
| **异构双盲校验（Dual-Blind Disagreement）** | 首轮全池精标时必须跨两个完全独立的模型会话运行（主控 Pass 1 + 异构盲审 Pass 2，不可见对方输出）；凡两边结果不一致的股票自动拎出，优先人工确认或锁定。 |
| **宽松滥标偏差（Liberal Inclusion）** | 大模型做多选题时的通病：看到公司简介里有 `"AI"`、`"Cloud"` 等公关词就手松乱打标。必须靠字典里的**硬性排除条款（Exclusion Criteria）**与正反例锚点压制。 |
| **叙事起点（`narrative_start_date`）** | 某个跨界大主题真正成为市场交易主线的大致起始年月（如 `AI 电力缺口` 始于 2024 年春）。上层算历史拥挤度分位时不能往前跨进“主题还没诞生的年代”，否则历史相关性分母过低会导致拥挤警报永久虚高。 |
| **`Comomentum`（残差联动拥挤度）** | 学术界衡量主题交易拥挤度的经典指标（Lou & Polk, 2022）：剔除大盘波动后，同一个篮子里的股票两两同涨同跌的紧密程度。至少需要篮子内有 4~5 只以上股票（≥ 6~10 对配对）才算得稳。 |
| **`CODE_VERSION_SOURCES` 哈希红线** | 景气引擎会对 `terminal/prosperity/version.py` 所列全部 11 项代码与配置路径（含 `market_store.py`、`settings.py`、`symbol_aliases.py`、`symbol_aliases.json` 等）做字节级哈希校验；新分类模块必须物理独立，确保实施前后 `code_version()` 完全相等。 |
| **仓外三明治隔离与锁内毫秒落库** | 周日 10:00 本机 `launchd` 跑前后置脚本，中间夹着不挂工作区、零命令权限的 AGY Sidecar（仅读写仓库外交换目录），校验通过后经受限 SSH 在云端写锁内执行 `<20ms` 幂等事务落库。 |
