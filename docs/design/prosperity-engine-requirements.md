# 美股基本面景气引擎 — 需求文档

> **日期**: 2026-09-25（2026-09-26 按 Boss 融合方案修订）
> **状态**: 已确认（2026-09-26）
> **来源**: 以朋友 Foresight「Fundamental Momentum」景气引擎（美股部分）为原型，融合现有 Premium 的 EPS 信号并改良；原站拆解结论见本文末「参考」
> **北极星定位**: 主北极星第二层「分析层 · 基本面」的量化维度；验证走「离线 R&D」

## 1. 动机

- 要的是**候选池雷达**：从扩展池里挑出基本面正在多因子共振、持续向好的少数股票。买不买、什么时候买，交给 Boss 的量价时机判断和 CIO-B / 深度分析。
- 是**筛股工具**，不是回测出来的交易信号，也不是自动交易策略。和 Boss 的定位一致：edge 在时机轴，基本面当过滤器；尽量少看盘。
- **替代现有 Premium 池**，成为唯一的精选池。融合方案见第 9 节（2026-09-26 Boss 定）。

## 2. 用户

- **Boss 本人**：看榜单，看每只票的景气分拆解。
- **晨报**：读取精选池，对池内标的的信号做提示（沿用 Premium 在晨报里的角色：标红、EMA30 时机门、RVOL 等）。
- 暂不接 CIO-B 和深度分析。落库的结构要让以后能接入。

## 3. 场景

- **周更 live 榜**：跟随每周六基本面 + forward 数据刷新之后更新，只用当时已发布的财报和当周预期快照。
- **财报季最终榜**：每个财报季结束时冻结一份阶段性最终榜（"财报季结束"的判定在 Phase 3 定）。历史各季的最终榜用于回看和体检报告。
- **随时查看**：我们自己的网页随时能看最新 live 榜和历史最终榜。
- **晨报日常**：每天读取最新精选池，对成员提示信号。
- **改良迭代**：改一版方案，自动产出体检报告，Boss 看完决定是否采用。

## 4. 产品形式

- **落库**：每期榜单的因子原始值、z 值、各方案分数和评级、数据质量标记。
- **精选池文件**：沿用 `premium_pool.json` 的形态，带 schema 校验和新鲜度检查，给晨报读。
- **网页榜单**：参照原站，可以切换方案和期数（周更 live / 财报季最终榜），点开看分数拆解；随时可访问。
- **体检报告**：每个方案一份 HTML。

## 5. 输入 / 输出

**输入**
- `market.db`：`income_quarterly` / `balance_sheet_quarterly` / `cash_flow_quarterly`（营收、成本、毛利、经营现金流、capex、FCF、净利润、EPS、filing_date）
- `fmp_earnings`：`announce_date` 判断数据何时可用（防前视）；adjusted 口径 `eps_actual` / `revenue_actual`（TTM PE 与一致预期同口径）；下次财报日
- `fmp_estimates`：FMP 季度 / 年度一致预期（EPS、营收、净利润），周频快照，2026-07-13 起。用于未来预测、预期修正、NTM PE
- `historical_market_cap` 与 `daily_price`：按当时市值确定 $10B+ 扩展池成员；PE 计算；前瞻收益和价格动量对照
- `forward_estimates`（yfinance，2026-03 起）：对拍参照，不作主输入
- **原站参照数据**：`data/external/foresight_fm/prosperity.json`（原站美股 47 期完整输出，gitignored，不外传），只用于共有因子的数据校验

**输出**
- 每期、每只股票一行：各因子原始值、z 值、趋势加减分、各方案分数与评级、NTM PE / TTM PE、β（仅展示）、数据质量和覆盖率
- 精选池 Top N（约 30–50，N 在体检报告里确定）
- 网页榜单、体检报告

## 6. 约束

- **时间范围 2021 起**：本地 `daily_price` 从 2021-02 开始。季报 2016 年起约 620 只以上，够满足"至少 6 季历史"。
- **只用 $10B+ 扩展池**：不搭原站那套成交额前 50 的股票池。
- **forward 数据只有 2026-07 起**：历史期没有 forward 因子，按覆盖率重新摊权（原框架机制），不伪造历史预期。
- **EPS 口径一致**：TTM PE 与 NTM PE 必须同为 adjusted 口径（TTM 用 `fmp_earnings.eps_actual` 求和），不得用利润表 GAAP EPS 与一致预期相除（issue036 教训）；近期拆股标的先交叉校验每股数据（issue035）。
- **数据写入所有权**：`market.db` 只允许云端写入；研究产物不写进本地 `market.db`。景气引擎的输出放哪、在哪一端计算，由 Phase 3 决定。
- FMP 调用串行；云端 Python 3.10；开发在 worktree 里进行；周六 cron 共用 `market_db_writer` 锁，串行执行。
- 门槛和打分因子都要能配置、能插拔。

## 7. 成功标准

**不设"跑赢谁"的上线门槛。** 回测只作为**体检报告**，Boss 看完拍板。

- **S1 数据校验**：用原站数据核对共有因子（营收同比、营收加速、毛利率及其同比、FCF 率同比、净利率同比），2021 年以后各期约 95% 的行差 < 0.5pp；其余逐个说明原因（FMP 重述、原站修复、缺季等）。不做分数 / 评级的逐行复刻（2026-09-26 Boss 确认）。
- **S2 扩展池版可用**：融合方案跑在 $10B+ 扩展池上，周更 live 榜和财报季最终榜都能生成，精选池文件通过校验，网页可访问。
- **S3 体检报告**：每个方案自动产出，内容包括：分层前瞻收益是否单调（带置信区间）、和价格动量的重叠度、行业集中度、换手率、典型失败案例。
- **S4 替代 Premium**：晨报从 Premium 切换到景气精选池，切换过程中晨报不能中断。
- **MVP = S1 + S2 + S3**（融合方案）。S4 在 Boss 看过首份体检报告后执行。

## 8. 风险

| 风险 | 后果 | 架构上怎么应对 |
|---|---|---|
| 样本小（2021 年起约 22 期） | 体检报告结论不可靠，调参容易过拟合 | 报告必须带置信区间；每次方案变更留档，写明改了什么、为什么。**不设留出样本**（系统用途是筛股，不是验证信号） |
| 没有上线门槛，调参不受约束 | 越改越拟合历史 | 方案注册表加变更日志；体检报告固定格式，不能为某个方案临时改口径 |
| 扩展池约 1000 只，行业构成和原站 50 只完全不同（银行、REIT、公用事业大量进来） | 跨行业 z 值可能失效；银行等"会计景气"刷榜 | 行业处理做成可配置项；主榜按跨行业打分，体检报告并列一版剔除金融/REIT/公用事业的对照；体检报告看行业集中度 |
| 环比受季节性和 53 周财年影响 | 零售 Q4 等季节性被读成景气 | 环比做季节调整（口径 Phase 2/3 定）；与"营收同比加速"的重复计权要处理 |
| 净利润 / EPS 基数小或为负 | 百分比增速爆炸或符号反转 | 最小基数门槛；亏损转盈单独标记；缺失即缺失，不填中性值 |
| forward 数据短、口径与财报不同 | 历史期无 forward 因子；PE 口径错配夸大估值变化 | 历史期按覆盖率摊权并在榜单标注；PE 同为 adjusted 口径 |
| 周更横截面混着不同季度的数据 | 已报 / 未报公司的因子不可比 | Phase 2/3 定处理方式（最新可用季度 vs 统一截面） |
| FMP 数据错误（NBIS 类），而且规模比原站大 20 倍 | 错数冲进 Top N | 复用现有 `fundamental_quality.py` 和数据质量层；异常值打标，不静默吞掉 |
| 扩展池成员没有按当时市值确定 | 幸存者偏差 | 按当期历史市值确定成员 |
| 低基数复苏被读成景气加速 | Top N 被算术"加速"占据 | 低基数守卫（两年叠加增速等） |
| 替代 Premium 时晨报依赖断掉 | 晨报出错或无声降级 | 并行过渡期；文件 schema 兼容；数据缺失时明确报错，不能当作空池放行 |
| 原站数据是私有的 | 泄露朋友的成果 | 只放 gitignored 目录，不进 git、不外发 |

## 9. 融合方案（2026-09-26 Boss 定）

1. **因子维度**：保留原框架的营收同比、营收加速、毛利率同比、毛利率、FCF 率同比；**去掉存货 / 库存周期**（含库存乘数和 capex 微调）。**增加环比**，维度是营业收入、净利润、EPS；净利润、EPS 的同比也进入打分。（2026-09-26 研究后细化：对数口径下季调环比 ≡ 同比加速度，所以"营收加速"即营收季调环比，另加 EPS 加速度；只用 EPS 计分，净利润放展示层；原始环比只展示。见研究文档 D1/D2。）
2. **Premium 规则**：EPS 同比 / 环比 ≥20%、4 季平均增速 ≥10% **只作为打分因子，不当硬门槛**；**β ≥1.35 去掉**，β 只在榜单上显示。
3. **更新节奏**：跟随每周基本面数据刷新，每周更新榜单；每个财报季结束冻结一份阶段性最终榜；网页随时可看。
4. **forward 维度**：用 forward 数据加入对未来的预测，以及 NTM PE、TTM PE 维度，具体用法 Phase 2/3 研究后提方案（候选：下季预期同比、NTM EPS 增速、预期修正进打分；PE 作展示层或可选护栏）。
5. **其他保持原框架**：winsorize z 值 → 按覆盖率重新摊权 → 0–100 映射 → 毛利率 8 季斜率加减分 → STRICT / FULL / BELOW（净利率守卫、次新三关）→ 组内分。原站 5 套权重对应的是旧因子集合，新因子集合的权重在 Phase 3 提出。

## 确认记录（2026-09-26）

- 定位：**筛股工具**，不是回测出来的交易信号。体检报告用来发现榜单有没有明显毛病，不作为上线门槛。
- 不设留出样本；防过拟合只靠方案变更日志和固定格式的体检报告。
- 行业：主榜跨行业打分，同时出一版剔除金融/REIT/公用事业的对照。
- 融合方案：见第 9 节。Premium 切换（S4）在首份体检报告之后。
- 原站复刻降为共有因子的数据校验。
- Phase 2 领域研究：3 个研究 subagent。

## 需求清单

- **R1**: 景气引擎融合方案：因子集合见第 9 节；μ±3σ 缩尾 z 值（截 ±3）、按覆盖率重新摊权、截 ±2 映射 0–100、毛利率 8 季斜率分档加减分（不截断）、STRICT / FULL / BELOW 闸门（净利率守卫、次新三关）、组内分
- **R2**: 防前视取数：以财报发布日判断可用，找不到时退回 filing_date；同比 / 环比要检测缺季和财年变更
- **R3**: 共有因子数据校验工具：用原站 fixture 逐行比对因子层，输出差异清单和原因分类
- **R4**: 按当期历史市值确定 $10B+ 扩展池成员，2021 年起
- **R5**: 方案注册表：权重、变换方式、门槛、因子集合都可以配置；多方案并列，不覆盖；留变更日志
- **R6**: 可插拔的门槛层和因子层
- **R7**: 周更 live 榜（挂在周六基本面 + forward 更新之后）+ 财报季最终榜（冻结）
- **R8**: 落库存储榜单明细，方便后续 CIO-B / 深度分析查询
- **R9**: 精选池文件（Top N），带 schema 校验和新鲜度检查，给晨报用
- **R10**: 网页榜单：随时可访问；切换方案和期数、分数拆解、NTM / TTM PE 与 β 展示、数据质量和覆盖率徽章
- **R11**: 体检报告：分层前瞻收益（带置信区间）、价格动量重叠度、行业集中度、换手率、失败案例；对照组包括扩展池均值、价格动量 Top N、现有 Premium 池
- **R12**: 数据质量层：复用现有基本面质量检查，并覆盖原站 R1–R12 中适用于 FMP 美股的规则
- **R13**: 环比因子（营收 / 净利润 / EPS，季节调整）与净利润、EPS 同比因子，含小基数 / 负基数处理
- **R14**: forward 因子层：未来预测（下季预期同比、NTM 增速等）、预期修正、NTM PE / TTM PE（adjusted 同口径）；历史期缺失按覆盖率摊权
- **R15**: 改良方案候选（MVP 之后）：两年叠加 / 对数增速、排名变换、净利率连续惩罚、低基数守卫、量价确认层
- **R16**: 晨报从 Premium 切换到景气精选池，需要并行过渡、兼容降级
